# xui-doctor

Небольшая программа, которая проверяет здоровье и настройки панелей
[3x-ui](https://github.com/MHSanaei/3x-ui) и её форка
[still-ui](https://github.com/Dv2Corn/still-ui). Работает только на чтение.

Она входит в API панели, читает статус сервера, входы (inbounds), хосты и
настройки и печатает, что сломано или рискованно, по уровням важности, а к
каждой находке - одну строку о том, как исправить. В панели она ничего не
меняет.

Вывод на одноразовой тестовой панели (длинные строки сокращены до "..."):

```
$ XUI_API_TOKEN=... xui-doctor check --url http://127.0.0.1:12053/doctor-test/
xui-doctor v0.1.0: http://127.0.0.1:12053/doctor-test
panel: 3x-ui 3.11.0, Xray 26.10.21, auth: API token

== CRITICAL ==
- [xray] inbound #1 "reality-ios" (vless, port 24443): Xray 26.10.21 (>= 26.9.8) refuses REALITY
  ClientHellos without an X25519MLKEM768 key share; share links here use fp=ios, which has none,
  so clients using them cannot connect
  fix: Set the uTLS fingerprint to chrome, firefox or safari and let clients refresh the
  subscription, or pin Xray 26.6.27 in the panel's Xray version switcher ...
- [xray] host "edge-host" -> inbound #1 "reality-ios" (vless, port 24443): ... this host has
  "Mihomo X25519" on, so its Clash subscription turns ML-KEM off and mihomo clients are refused
- [tls] inbound #4 "trojan-tls-inline" (trojan, port 24445) inline certificate: certificate
  expired on 2026-11-01 23:25 UTC
  fix: Replace the inline certificate with a renewed one.

== WARN ==
- [xray] REALITY clients: ... sing-box based clients (sing-box, Hiddify, Karing, NekoBox; tested
  1.12.12 and 1.14.4) cannot connect with any fingerprint; ...
- [clients] clients: 1 client has an IP limit (limitIp) but fail2ban is not usable on the panel
  host (enabled=no, installed=no, usable=no), so the limit is not enforced
- [security] login: two-factor authentication is off
  fix: Enable it in Settings -> Authentication -> Two-factor authentication.

== INFO ==
- [tls] TLS inbounds: 1 certificate file not checked; run with --local on the panel host to read them

summary: 4 critical, 3 warn, 1 info, 3 ok
(OK lines hidden; use --verbose to show them)
```

Тот же отчёт по-русски - в разделе [Язык вывода](#язык-вывода).

## Какие панели поддерживаются

| Панель | Проверено на | Примечания |
|---|---|---|
| 3x-ui (MHSanaei) | v3.11.0 (образ Docker `ghcr.io/mhsanaei/3x-ui:v3.11.0`) | API v3.x; старые панели 2.x могут работать частично (не проверялось) |
| still-ui (Dv2Corn) | v1.3.0 (архив выпуска) | определяется по полю `upstreamVersion` в статусе сервера |

Программа пишет, какую панель она нашла. При проверке версии 3x-ui
сравнивается с последним выпуском `MHSanaei/3x-ui`, а still-ui - с последним
выпуском `Dv2Corn/still-ui`.

## Установка

```
go install github.com/Dv2Corn/xui-doctor/cmd/xui-doctor@latest
```

или соберите статический бинарник (без CGO, только стандартная библиотека):

```
CGO_ENABLED=0 go build -trimpath -ldflags "-s -w" -o xui-doctor ./cmd/xui-doctor
```

## Запуск

```
xui-doctor check --url https://HOST:PORT/BASEPATH/ [--insecure] [--json] [--local]
                 [--dial-targets] [--offline] [--verbose] [--timeout 20s] [--lang en|ru]
```

Учётные данные берутся только из переменных окружения, чтобы они не попали в
историю команд и в список процессов:

| Переменная | Что это |
|---|---|
| `XUI_API_TOKEN` | токен API (Settings -> Authentication -> API tokens). Токен *Administrator* читает всё; токен *Monitoring* позволяет только проверки Xray и версии. |
| `XUI_USERNAME`, `XUI_PASSWORD` | логин панели, если токен не задан |
| `XUI_2FA_CODE` | текущий код 2FA, если она включена |
| `XUI_URL` | значение `--url` по умолчанию |

| Ключ | Что делает |
|---|---|
| `--url` | адрес панели вместе с её путём (URI path, base path); адрес с логином и паролем внутри не принимается |
| `--insecure` | принять самоподписанный сертификат панели или сертификат на другое имя |
| `--json` | вывод для программ |
| `--local` | программа запущена на сервере панели: ещё прочитать файлы сертификатов и слушающие сокеты (`/proc/net`) и проверить цели REALITY оттуда (включая локальные и частные адреса) |
| `--dial-targets` | проверить цели REALITY с той машины, где запущена программа (так и пишется в отчёте: это может быть не сервер панели); цели, которые указывают на loopback, частные, link-local, CGNAT, документационные, NAT64/6to4 и прочие особые адреса IANA, пропускаются |
| `--offline` | не спрашивать GitHub о последнем выпуске |
| `--verbose` | печатать и строки OK |
| `--lang` | язык вывода, `en` или `ru`; без ключа русский включается русской локалью (`LC_ALL`, `LC_MESSAGES` или `LANG` начинается с `ru`, проверяются в этом порядке), иначе вывод на английском |

Код выхода: `0` - ничего серьёзнее INFO, `1` - есть предупреждения, `2` - есть
критичные находки, `3` - проверка не выполнена (неверный адрес, панель не
пустила, ...).

### Язык вывода

Текстовый отчёт печатается по-английски или по-русски. Русский включается
ключом `--lang ru` или сам, если локаль русская: берётся первая непустая
переменная из `LC_ALL`, `LC_MESSAGES`, `LANG`, и если она начинается с `ru`
(например, `ru_RU.UTF-8`), вывод будет на русском. `--lang en` возвращает
английский при любой локали. Подсказка `xui-doctor help` и сообщения об
ошибках тоже переводятся.

Уровни (`CRITICAL`, `WARN`, `INFO`, `OK`) и номера проверок (`xray`, `tls`, ...)
остаются как есть, названия настроек панели - тоже. Вывод `--json` всегда на
английском, а у каждой находки есть постоянный `id` сообщения, чтобы скрипты не
зависели от формулировок и локали.

Отчёт с `--lang ru` по записанным ответам той же тестовой панели
(`testdata/3x-ui-3.11.0`, вход по паролю; часть находок и длинные строки сокращены до "..."):

```
панель: 3x-ui 3.11.0, Xray 26.10.21, авторизация: пароль

== CRITICAL ==
- [xray] вход #1 "reality-ios" (vless, порт 24443): Xray 26.10.21 (>= 26.9.8) не пускает по REALITY
  ClientHello без ключа X25519MLKEM768; ссылки здесь с fp=ios, а в нём такого ключа нет, и клиенты
  по ним не подключатся
  что делать: Поставьте отпечаток uTLS chrome, firefox или safari и пусть клиенты обновят подписку,
  или закрепите Xray 26.6.27 в выборе версии Xray в панели ...
- ...
- [tls] вход #4 "trojan-tls-inline" (trojan, порт 24445), встроенный сертификат: сертификат истёк
  2026-11-01 23:25 UTC
  что делать: Замените встроенный сертификат новым.

== WARN ==
- ...
- [clients] клиенты: у 1 клиента задан лимит IP (limitIp), но fail2ban на сервере панели не работает
  (enabled=no, installed=no, usable=no), так что лимит не соблюдается
- [security] вход в панель: двухфакторная аутентификация выключена
  что делать: Включите её: Settings -> Authentication -> Two-factor authentication.

== INFO ==
- [tls] входы TLS: 1 файл сертификата не проверен; чтобы их прочитать, запустите с --local на сервере панели

итого: CRITICAL 4, WARN 3, INFO 2, OK 2
(строки OK скрыты; показать их: --verbose)
```

### Что программа отправляет

Только эти запросы, относительно адреса панели:

- `GET /csrf-token`, `POST /login`, `POST /logout` - своя сессия (с токеном не нужны);
- `GET /panel/api/server/status`, `GET /panel/api/inbounds/list`,
  `GET /panel/api/hosts/list`, `GET /panel/api/server/fail2banStatus`;
- `POST /panel/api/setting/all` - это чтение; панель принимает его как POST и
  в ответе затирает секреты (токены ботов, секрет 2FA).

С `--local` или `--dial-targets` она ещё делает TLS-рукопожатия с целями
REALITY: каждое имя разрешается один раз, и подключение идёт на проверенный
адрес (таймаут 5 с, не больше 20 рукопожатий за запуск; пропущенные
перечисляются). Без `--local` на непубличные адреса целей она не подключается
никогда; адрес, к которому идёт подключение, проверяется ещё раз в момент
соединения.

И, если нет `--offline`, - один анонимный запрос к
`api.github.com/repos/<repo>/releases/latest`. UUID и пароли клиентов и
закрытые ключи REALITY читаются в память, только чтобы сравнить их между
собой, и никогда не печатаются.

## Проверки

| ID | На что смотрит |
|---|---|
| `xray` | состояние и версию Xray с учётом изменений REALITY (см. ниже); отпечатки uTLS входов REALITY и хостов подписки; переключатель "Mihomo X25519" у хостов |
| `reality` | target, serverNames, privateKey, shortIds - ровно так, как их проверяет Xray-core; пустой открытый ключ для ссылок; `show`; с `--local`/`--dial-targets`: TLS 1.3, h2 и действительный сертификат у цели для каждого serverName |
| `tls` | срок встроенных сертификатов входов TLS и сертификата, который показала панель; с `--local` ещё файлы сертификатов входов, панели и сервера подписки (истёк: CRITICAL, меньше 7 дней: WARN) |
| `ports` | включённые входы (и панель / сервер подписки), которые займут один порт и транспорт на одном адресе, по тем же правилам TCP/UDP, что и сама панель; с `--local` - включённые входы, которые никто не слушает |
| `clients` | клиенты с истёкшим сроком или исчерпанным трафиком, но всё ещё включённые; два клиента с одним UUID/паролем внутри входа; лимиты IP при неработающем fail2ban |
| `security` | admin/admin (только если вы запустили программу с ними), обычный HTTP, путь `/`, порт по умолчанию 2053 и пути подписки по умолчанию, выключенная 2FA, заданный токен бота Telegram |
| `version` | версию панели против последнего выпуска на GitHub |

Входы, которые работают на удалённых узлах, пропускаются проверками, которым
нужен локальный Xray; запустите программу отдельно для каждого узла.

### Проверки, от которых отказались

- *Одна почта на нескольких входах* - с 3x-ui 3.x клиент - это одна запись,
  которую специально можно привязать к нескольким входам.
- *Формат spiderX* - панель сама выводит для каждого клиента `spx`, который
  всегда начинается с `/`.
- *Версия бинарника Xray на диске* - API статуса и так сообщает версию
  работающего ядра.
- *Подбор паролей по умолчанию* - программа никогда не пробует пароли; она
  отмечает admin/admin, только если вы сами запустили её с ними.

## Зачем нужна проверка Xray

Два изменения в официальном сервере REALITY в Xray-core ломают клиентов,
которые раньше работали, и панель об этом ничего не говорит:

1. **26.7.11 - 26.7.28:** у серверов REALITY `minClientVer` по умолчанию
   26.3.27
   ([Xray-core af7eb680](https://github.com/XTLS/Xray-core/commit/af7eb68028732a8ee3c0e5d6ab2b8a657bb2e770)).
   Клиенты, которые не сообщают версию Xray (sing-box, mihomo), и клиенты Xray
   версий ниже 26.3.27 получают отказ, если во входе не задан `minClientVer`
   явно.
2. **26.9.8 и новее:** сервер отвергает любой ClientHello, в котором нет
   ключа X25519MLKEM768 перед необязательным X25519
   ([XTLS/REALITY 8cdf7bf9](https://github.com/XTLS/REALITY/commit/8cdf7bf9c7f09cb9814bf08c3eb877f68b85fba8),
   в Xray-core пришло коммитом
   [47cfe999](https://github.com/XTLS/Xray-core/commit/47cfe9994a6b39b1f673ba35e62b091bcce15a71), впервые в
   v26.9.8; этот тег в основном репозитории удалён, первый опубликованный
   выпуск - v26.9.9). В том же выпуске значение `minClientVer` по умолчанию
   снова закомментировано. Отвергнутый hello считается посетителем без
   REALITY и уходит к цели, так что клиент видит настоящий сертификат цели.

Таблица проверки (официальные бинарники, всё на loopback, цель `www.nvidia.com`,
4 запроса на клетку; скрипт в [`tools/reality-matrix`](tools/reality-matrix)):

| Сервер | клиент Xray chrome / firefox / safari | клиент Xray ios / edge / qq | sing-box 1.12.12 и 1.14.4, любой fp | mihomo 1.19.33 | mihomo + `support-x25519mlkem768: true`, chrome |
|---|---|---|---|---|---|
| 26.6.27 | ok | ok | ok | ok | ok |
| 26.7.28 | ok | ok | отказ | отказ | отказ |
| 26.9.9 | ok | **отказ** | **отказ** | **отказ** | ok |
| 26.10.31 | ok | **отказ** | **отказ** | **отказ** | ok |

Клиенты Xray 26.6.27 и 26.10.31 ведут себя одинаково. `android` и `360` в этой
схеме не прошли ни с одним сервером, `random`/`randomized*` выбирают новый hello
на каждое соединение и работают только иногда. Тот же результат и целиком
через панель: на 3x-ui 3.11.0 (в комплекте Xray 26.10.21) и still-ui 1.3.0
(Xray 26.10.31) вход с `fp=ios` дал 0/3 для клиента Xray с fp ios, 3/3 с chrome
и safari и 0/3 для sing-box 1.14.4.

Что делать - как и пишут находки: сменить отпечаток в ссылках на chrome,
firefox или safari либо закрепить Xray 26.6.27 в выборе версии Xray в панели.
Hello с ML-KEM больше - замер на Xray 26.10.31: chrome 1820, firefox 1889,
safari 1537 байт против 517 у ios/edge/qq - и не влезает в один TCP-сегмент, с
чем некоторые мобильные сети справляются плохо. Подписка Clash самой панели
уже ставит `support-x25519mlkem768: true` для клиентов mihomo; хост с
включённым "Mihomo X25519" это выключает.

Пропатченное ядро, которое по-прежнему принимает старые hello, сообщает ту же
строку версии; программа их не различает, так что читайте находки `xray` с
этой поправкой.

## Разработка

```
go vet ./...
go test ./...
```

Сообщения лежат в `internal/i18n/catalog.go`, на английском и русском. Тест
падает, если у сообщения нет русского текста, если в двух текстах разные
форматные глаголы (`%s`, `%d`, ...) или если код использует ID, которого нет в
каталоге.

В `testdata/` - ответы, записанные с одноразовых панелей 3x-ui 3.11.0 и
still-ui 1.3.0; UUID, ключи, пароли и GUID в них заменены ненастоящими.
`internal/doctor` проигрывает их через поддельную панель с теми же правилами
CSRF и сессий, и тест падает на любом запросе вне списка «только чтение»
выше.
